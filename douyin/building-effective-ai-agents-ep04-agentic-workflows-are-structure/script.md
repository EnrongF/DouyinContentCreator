# Script

Voice direction: calm executive documentary, natural Mandarin, measured but not slow. Keep English terms clear.

Workflow 讲的是任务怎么被组织：先后、并行、评估和优化。它不是多智能体协调概念的同义词。

和 Agent 的动态行为不同，Workflow 更强调预定义控制流。你知道大致步骤，才适合把流程结构化。

顺序工作流适合阶段依赖明显的任务，比如草稿、审查、润色。每一步产出，都是下一步输入。

并行工作流适合互不依赖的子任务。风险、合规、运营可以同时看，但如果彼此必须接力，就不要硬并行。

Evaluator-optimizer 是生成和评估的迭代循环。它适合有清晰评价标准、需要反复改进的内容。

如果任务一步就能完成，或者评价标准不清楚，Workflow 只会增加延迟和维护成本。

选择顺序、并行还是评估优化，不是看哪个更高级，而是看任务之间有没有依赖、能不能独立处理、有没有质量标准。

第四集的结论是：Workflow 是结构工具。它可以服务 Single Agent，也可以服务 Multi-Agent，但不要把它们混成一层。
