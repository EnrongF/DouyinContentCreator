# The Founder's Playbook: Source Logic / Taxonomy Gate

## Milestone Status

Decision: **Pass to Series / Episode Scope Gate. Do not proceed to compression, script, voice, visual, or video yet.**

Lead conclusion: this PDF should be processed as a **mini-series**, not one video. The source has one strong umbrella thesis, but it contains several separate mental upgrades that would be weakened if compressed into a single episode.

Source frame:

```text
AI compresses execution
-> founder judgment becomes the tighter bottleneck
-> each startup stage exposes a different failure mode
```

Source taxonomy to preserve:

```text
Idea
-> MVP
-> Launch
-> Scale
```

Do not flatten this into generic "AI startup tips".

## Role Assessments

### Knowledge

Recommendation: **series, not one episode**.

Reasoning:
- The source supports one umbrella thesis: AI makes execution cheaper, so judgment becomes scarcer.
- The actual structure is lifecycle-based: Idea, MVP, Launch, Scale.
- Each stage has different failure modes, exit criteria, and operational artifacts.
- A single episode would demote too many episode-core claims into rushed mentions.

Key warning:
- Do not promote child artifacts such as `CLAUDE.md`, scope docs, security review, or measurement frameworks into peer-level source categories. They are supporting mechanisms under stage logic.

### Quality

Recommendation: **park for production; pass only to gates**.

Reasoning:
- The source is useful, but not yet safe for publishable compression.
- Provenance is not explicit enough.
- Claude / Anthropic framing is strong and could become vendor-shaped doctrine.
- Several public claims need verification before use.

Required guardrails:
- Attribute the source as Claude / Anthropic-centered unless provenance is independently confirmed.
- Treat Claude-specific product guidance as examples, not universal startup law.
- Do not use metrics, founder stories, or product availability claims without verification.
- Keep the caveat that execution still matters; the claim is bottleneck shift, not execution disappearance.

### Douyin Platform

Recommendation: **one flagship opener plus focused follow-up episodes**.

Reasoning:
- Audience viability is high for founders, indie hackers, AI builders, product operators, and investors.
- Strongest tension: AI makes building easy, but also makes wrong decisions easier to execute completely.
- One broad summary would hurt retention and follower conversion.

Best opener:

```text
AI 让创业变快了，但也让你更容易把错东西做得很完整。
```

Voice note:
- This sentence is useful as a strategic hook, but it is not final voice copy. `把错东西做得很完整` is understandable but slightly translated / written for spoken Chinese.
- Owner: **Voice** rewrites all hooks into native spoken Chinese before script approval.
- Secondary gate: **Quality** checks whether the rewritten line preserves the source claim and avoids overclaiming.

Native spoken candidates:

```text
AI 让创业变快了，但也让你更容易一口气做出一个没人要的东西。
AI 让你做得更快，也让你更容易把方向错的产品一路做下去。
AI 让产品更容易做出来，也让错误方向更难早点停下来。
```

Weak angles to avoid:
- `如何用 Claude 做一家 AI 创业公司`
- `AI 创业四步法`
- `2026 创业完全变了`
- unverified founder success stories

### Voice / Visual Production

Recommendation: **feasible as a short series; risky as one dense video**.

Reasoning:
- Voice will become stiff if English startup vocabulary is translated literally.
- Visuals should use one dominant metaphor per episode.
- A full lifecycle map plus all failure modes will exceed mobile readability.
- Existing warm technical brand style can be a family reference, but the Founder Playbook needs a distinct "founder decision gate" metaphor rather than reusing agent-system diagrams.

Native Chinese direction:

```text
AI 让创业变快，但也让判断变得更贵。
```

Avoid:

```text
AI-native 创业的执行压缩导致创始人判断稀缺。
```

## Proposed Series Shape

Series working title:

```text
AI-native 创业的新瓶颈：不是执行，是判断
```

### Episode 1: Judgment Bottleneck

Working claim:

```text
AI 让执行变便宜，创始人的判断变成瓶颈。
```

Function:
- Opens the series.
- Explains why the lifecycle must be split.
- Teases the four stage risks without teaching all of them.

Non-cuttable caveat:
- Do not imply execution no longer matters.

### Episode 2: Idea

Working claim:

```text
原型不是验证。
```

Function:
- Teaches the risk of mistaking "can build" for "should build".
- Connects AI build speed to false validation.

Non-cuttable source anchors:
- Sense-making before building.
- Prototype as conversation prop, not PMF evidence.

### Episode 3: MVP

Working claim:

```text
AI 写得越快，越需要边界和上下文。
```

Function:
- Teaches agentic technical debt as context drift and architecture drift.
- Keeps the frame on founder / MVP risk, not generic Claude Code workflow.

Non-cuttable source anchors:
- Architecture principles before code.
- Persistent context.
- Scope boundaries.

### Episode 4: Launch

Working claim:

```text
上线以后，创始人不能还在每个回路里。
```

Voice note:
- This is a useful visual / systems concept, but not final spoken Chinese. `每个回路里` sounds technical and translated in voiceover.
- Owner: **Voice** should rewrite it as native founder/operator language.
- Secondary gate: **Quality** should ensure the rewrite preserves the Launch-stage claim: founder attention must be replaced by repeatable systems, not removed irresponsibly.

Native spoken candidates:

```text
上线以后，创始人不能还是什么事都亲自盯。
产品上线后，创始人不能继续当所有事情的中转站。
上线之后，如果每个问题都还要创始人接住，公司就没有真正进入增长。
上线以后，重点不是创始人更忙，而是把重复发生的问题变成系统。
```

Function:
- Teaches why founder-in-the-loop becomes a bottleneck after launch.
- Connects launch to repeatable operating systems.

Boundary:
- Launch is not Scale. This episode is about replacing founder attention with systems before broad expansion.

### Episode 5: Scale

Status: **conditional / later**.

Working claim:

```text
AI-native 的护城河，是工作流里攒出来的具体性。
```

Voice note:
- This is acceptable as an internal synthesis label, but not final voice copy. `具体性` is conceptually accurate but sounds abstract and unnatural in Chinese voiceover.
- Owner: **Voice** should convert it into concrete spoken Chinese.
- Secondary gate: **Quality** should ensure the rewrite does not overclaim defensibility beyond the source.

Native spoken candidates:

```text
AI-native 公司的护城河，不是模型权限，而是你在业务流程里一点点攒下来的行业细节。
AI 公司真正难复制的，不是用了哪个模型，而是它把业务怎么跑、用户怎么用、哪些坑不能踩，都沉进了自己的工作流里。
护城河不是一句“用了 AI”，而是你的工作流里积累了别人拿不走的细节。
```

Function:
- Teaches workflow specificity as defensibility.

Gate condition:
- Needs stronger evidence, examples, or secondary support before script approval.
