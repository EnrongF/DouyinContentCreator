# Sources

Put raw source files or links here for the project run.

## Suggested contents
- Source bundle manifest
- Input notes
- Reference links
- Extracted artifacts if you need a local copy

## Naming
Use descriptive article or topic slugs.

Pattern:
- `<source-or-topic-slug>.sources.md`

## Source Quality Checklist
- Latest: is this current enough for the topic?
- Frontier: does it represent current expert or state-of-the-art knowledge?
- Professional: is the author or institution credible in the domain?
- Original: is it primary or first-party evidence?
- Relevance: does it directly answer the research objective?
- Risk: could the source mislead because of bias, outdated information, weak evidence, or unclear provenance?

## Source Types
- Preferred: official documentation, first-party engineering posts, research papers, standards, release notes, datasets, conference talks, direct transcripts.
- Acceptable with label: high-quality secondary analysis from credible experts.
- Avoid: SEO summaries, reposts, unsourced commentary, outdated tutorials, content farms.
