## Topic Promise

Help founders and AI builders understand the real shift in AI-native startup work:

```text
AI makes execution faster, so the scarce thing becomes founder judgment.
```

```text
AI 让创业变快，但真正变贵的是判断。
```

## Audience

- Founders and solo builders using AI tools to research, code, launch, or operate products.
- Product and growth operators trying to separate real traction from fast-looking activity.
- Technical builders using Claude Code / coding agents who need product and architecture judgment.
- AI-curious investors or decision makers who want a clearer model for AI-native company building.

## Source Value Inventory Summary

Non-cuttable source values:
- AI compresses execution work across research, coding, documents, and operations.
- The founder bottleneck shifts from doing every task to deciding what should be built, validated, systematized, delegated, and defended.
- The lifecycle is source-defined: `Idea -> MVP -> Launch -> Scale`.
- Prototype existence is not validation.
- Problem-solution fit must come before MVP build confidence.
- PMF evidence requires behavior such as return, payment, referral, or repeated use.
- Agentic technical debt comes from context drift, architecture drift, and cheap feature expansion.
- Launch readiness includes replacing founder attention with repeatable systems.
- Claude / Anthropic product details are source examples, not universal startup law.

Moved or conditional values:
- `42%` startup failure claim: verify before public use.
- Sean Ellis test framing: verify before public use.
- Claude Code Security or specific product availability claims: verify before public use.
- Startup examples in the PDF: verify before public use.
- Scale / moat claims: keep in the map, but do not approve for script until stronger examples or evidence are available.

## Episode 1: AI 创业，真正卡的是判断

### Hook Angle

Native voice candidate:

```text
以前创业常常卡在做不出来。现在，AI 让你更容易把方向错的产品一路做下去。
```

Shorter variant:

```text
AI 让创业变快了，但真正变贵的是判断。
```

### Core Idea

AI compresses execution. That does not make execution irrelevant. It moves the hard part upward: the founder must make better decisions about what to research, build, validate, launch, systematize, and defend.

### Practical Takeaway

Before accelerating the work, define the decision gate:

```text
现在缺的是速度，还是缺判断？
```

### Source Concepts Retained

- Execution compression.
- Founder role shift.
- Same job, new rules.
- Lifecycle map: `Idea -> MVP -> Launch -> Scale`.
- Caveat: execution still matters.

### Moved Out

- Idea-stage validation mechanics move to Episode 2.
- MVP architecture and context management move to Episode 3.
- Founder bottleneck removal moves to Episode 4.
- Moat / workflow specificity moves to Episode 5 and remains conditional.

### Bridge To Next Episode

```text
第一个判断关口，不是怎么做 MVP，而是你有没有把 Demo 当成验证。
```

## Episode 2: 有 Demo，不代表有人要

### Hook Angle

Native voice candidate:

```text
AI 时代最危险的错觉，是东西已经做出来了，就以为问题被验证了。
```

### Core Idea

The Idea stage is not about producing a polished prototype. It is about understanding whether a real, specific problem exists and whether the proposed solution addresses that problem.

### Practical Takeaway

Use the prototype as a conversation prop, not as proof.

Decision question:

```text
用户是在夸你的 Demo，还是在暴露一个真的痛点？
```

### Source Concepts Retained

- Sense-making before building.
- Prototype is not validation.
- Problem-solution fit.
- Customer interview audit.
- Disconfirming evidence.
- Five-interview synthesis loop.

### Moved Out

- PMF measurement framework moves to Episode 3.
- Launch traction interpretation moves to Episode 4.
- Founder moat discussion moves to Episode 5.

### Bridge To Next Episode

```text
当你确定值得做，下一关不是让 AI 拼命写代码，而是先别让产品失控。
```

## Episode 3: 先定边界，再让 AI 写

### Hook Angle

Native voice candidate:

```text
AI 写代码很快，但如果产品边界不清楚，它也会很快把产品写散。
```

### Core Idea

Agentic technical debt is not only bad code. It is the loss of shared context, architecture principles, and product boundaries across fast AI-assisted build sessions.

### Practical Takeaway

Before adding more features, write down the constraints:

```text
这个产品现在只解决什么？暂时不解决什么？
```

### Source Concepts Retained

- Agentic technical debt.
- Architecture principles before code.
- Persistent context such as `CLAUDE.md`.
- Scope document.
- Zero-friction scope creep.
- Measurement framework before launch.

### Moved Out

- Detailed Claude Code workflow tutorial is not part of this episode.
- Security product claims move to verification.
- Launch operations move to Episode 4.

### Bridge To Next Episode

```text
产品能跑以后，真正的考验不是再多加功能，而是创始人能不能从每件事里退出来。
```

## Episode 4: 上线后，创始人别当中转站

### Hook Angle

Native voice candidate:

```text
产品上线后，创始人不能继续当所有事情的中转站。
```

Alternative:

```text
上线以后，如果每个问题都还要创始人接住，公司就没有真正进入增长。
```

### Core Idea

Founder involvement is useful in the MVP stage, but after launch it becomes a bottleneck if every decision, support issue, report, and process still depends on the founder.

### Practical Takeaway

Turn repeated founder attention into repeatable systems:

```text
哪些问题每周都会出现？哪些可以被流程、文档、指标或工具接住？
```

### Source Concepts Retained

- Founder bottleneck at Launch.
- Repeatable channel-driven growth.
- Production workload readiness.
- Operations without founder bottlenecks.
- Bottleneck map.

### Moved Out

- Scale governance and enterprise readiness move to Episode 5 or later.
- Expansion before readiness stays as supporting material unless needed for clarity.

### Bridge To Next Episode

```text
当系统能接住增长，下一关才是：别人为什么复制不了你？
```

## Episode 5: 护城河藏在业务流程里

Status: **conditional / later**.

### Hook Angle

Native voice candidate:

```text
护城河不是一句“用了 AI”，而是你的工作流里积累了别人拿不走的细节。
```

Alternative:

```text
AI-native 公司的护城河，不是模型权限，而是业务流程里一点点攒下来的行业细节。
```

### Core Idea

At Scale, defensibility comes from accumulated specificity: domain knowledge, workflow depth, integrations, behavioral data, governance, and user lock-in.

### Practical Takeaway

Ask what the company is learning that competitors cannot copy by simply using the same model.

Decision question:

```text
你的 AI 系统里，沉淀了哪些只有你才有的业务细节？
```

### Source Concepts Retained

- Domain knowledge.
- Workflow depth.
- Integrations.
- Proprietary behavioral data.
- User lock-in.
- Reduced direct founder dependence.
- Workflow integration audit.

### Moved Out

- Any claim of strong moat remains conditional until examples are verified.
- Startup examples require verification before use.
- Governance and enterprise readiness may become separate follow-up material if this episode becomes overloaded.
